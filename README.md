# なぞり書き練習アプリ（すうじ・ひらがな・カタカナ）

現場で働くフィリピン人介護士向けの、手書き文字練習PWAです。数字・ひらがな・カタカナを1つのアプリでなぞり書き練習でき、練習の進捗をLINE WORKSで共有できます。

対象ファイル：`nazori-practice-app.html`（単一HTMLファイル、外部依存はTailwind CDNのみ）

---

## 1. 特徴

- **3モード対応**：すうじ（0-9）／ひらがな／カタカナを1画面で切り替え
- **かなの完全網羅**：清音・濁音・半濁音・拗音・促音・長音（が・ぱ・きゃ・っ・ー など）まで練習可能
- **日英バイリンガルUI**：右上のボタンでJP/EN切り替え
- **なぞり書きキャンバス**：十字＋対角線（米字）ガイド付き、ペンの太さ調整可
- **参考スコア機能**：書いた文字とガイド文字の重なり具合を0〜100%で簡易採点（音声フィードバック付き）
- **反復練習と進捗記録**：文字ごとの練習回数・ベストスコアを端末内に保存し、選択バーにバッジ表示
- **音声読み上げ**：Web Speech APIで文字の発音を確認可能
- **LINE WORKS共有**：練習の進捗レポート画像（PNG）を生成し、スマホの共有シートからLINE WORKSへ直接送信可能

---

## 2. 使い方（練習する人向け）

1. 上部のボタンで練習したい種類を選ぶ：`123`（すうじ）／`あ`（ひらがな）／`ア`（カタカナ）
2. ひらがな・カタカナを選んだ場合は、その下のタブで「清音／濁音・半濁音／拗音・促音」を選ぶ
3. 下部の横スクロールバーから練習したい文字をタップする（🔊発音ボタンで読み方を確認できる）
4. 薄く表示された文字をキャンバスになぞって書く
5. 「消す」で書き直し、「採点する」でスコアを確認できる。**同じ文字は何度でも書き直してOK**（練習回数とベストスコアが自動で記録される）
6. 「次へ」「戻る」で文字を進める・戻る
7. ある程度練習が進んだら、下の「進捗をLINE WORKSに共有」からレポート画像を送信する

**選択バーの色の意味**
- 色なし：まだ練習していない文字
- 🟡 黄ドット：練習したが、ベストスコアが70%未満
- 🟢 緑ドット：ベストスコア70%以上（習熟の目安）

---

## 3. LINE WORKS共有機能について

「進捗をLINE WORKSに共有」ボタンを押すと、以下の情報をまとめた画像（PNG）がその場で生成されます。

- すうじ／ひらがな／カタカナ別の「練習済み文字数」「のべ練習回数」「平均スコア」「習熟(70%以上)文字数」
- 入力した名前（任意項目、一度入力すれば端末に保存され次回以降も自動入力）

生成後、スマホのシステム共有シート（Web Share API）が開き、LINE WORKSがインストールされていれば共有先として選択できます。

**注意点**
- **HTTPS環境が必須**です。Vercelなど実際のドメインにデプロイした状態でのみ動作します。ローカルファイルやプレビュー画面（iframe）では共有シートが開かない場合があります。
- Web Share APIの`files`共有に対応していない古いブラウザでは、自動的に画像がダウンロードされ、手動でLINE WORKSに添付するよう案内が出ます（iOS Safari 15以降・Android Chromeは概ね対応）。
- 進捗データは**各自の端末のブラウザ内（localStorage）にのみ保存**されます。サーバーには一切送信されません。共有した時点でのスナップショット画像だけが本人の意思でLINE WORKSに渡る仕組みです。

---

## 4. データの保存場所と限界（重要）

- 進捗（練習回数・ベストスコア・お名前）はすべて**端末のブラウザに個別保存**（localStorage）です。
- 50人がそれぞれ自分のスマホで使う想定のため、**人事・管理者側が全員の進捗を一覧で見る手段は今のところありません**。個人がLINE WORKSで手動共有した分だけが可視化されます。
- 端末のブラウザデータを消去（キャッシュクリア等）すると、その端末の進捗記録は失われます。
- 「採点」は正式なOCR判定ではなく、書いたインクとガイド文字の重なり具合を粗く計算した**めやす**です。厳密な字形評価ではないため、参考程度に扱ってください。

複数人分の進捗を人事側で集約・可視化したい場合は、Supabase等へのデータ送信＋管理者ダッシュボードの追加開発が別途必要です（本READMEの「今後の拡張案」参照）。

## 5. デプロイ方法（GitHub + Vercel）

いつものワークフローと同じです。

```bash
# 1. リポジトリに配置（ファイル名はindex.htmlにリネーム推奨）
mv nazori-practice-app.html index.html

# 2. Gabay-Manila などのGitHub Organizationにpush
git add index.html
git commit -m "add nazori writing practice app"
git push origin main

# 3. Vercelでリポジトリをインポート（フレームワークプリセット：Other / 静的HTML）
```

単一HTMLファイルのため、ビルドステップは不要です。Vercelの静的ホスティングでそのまま公開できます。

## 6. 技術メモ

- **構成**：単一HTMLファイル、Tailwind CSS（CDN版）、Vanilla JS
- **依存関係なし**：npm buildやフレームワーク不要。オフライン配布や軽量运用の方針に準拠
- **Tailwind CDNの警告について**：ブラウザのコンソールに「should not be used in production」という警告が出ますが、50人規模の社内配布・単一HTMLでの軽量運用という設計方針では実害はなく、無視して問題ありません
- **主要な内部関数**
  - `dataset` … 文字データ（すうじ／ひらがな／カタカナ×清音・濁音・拗音）
  - `computeMatchScore()` … 参考スコアの計算ロジック
  - `aggregateStats()` / `buildProgressCard()` … 進捗集計とレポート画像生成
  - `loadProgress()` / `recordAttempt()` … localStorageへの進捗保存

### 文字やヒントメッセージを追加・編集したい場合

`hiraSeion` / `hiraDaku` / `hiraYouon`（カタカナは`kata`系）の配列に文字を足すか、`numData`のオブジェクトに`notice_ja` / `notice_en`を追記するだけで反映されます。デザインやロジックの変更は不要です。

## 9. 既知の制約

- キャンバスのDPRスケール処理は修正済みですが、極端に古い端末では描画がわずかにズレる可能性があります
- 参考スコアはフォントレンダリングに依存する簡易計算のため、端末やブラウザによって数%のばらつきが出ます
- LINE WORKS宛の自動集約送信（Bot連携）は未対応です（上記「今後の拡張案」参照）# Nazori-practice-app
